# Рабочий процесс AFT PRO

- После выполнения запрошенных правок и необходимых проверок сразу создавать коммит с относящимися к задаче файлами и отправлять изменения в `origin/main`. Пользователь заранее разрешил этот рабочий процесс; повторное подтверждение не требуется.
- После отправки проверять результат публикации GitHub Pages и давать в итоговом ответе прямую ссылку на сайт, а при изменении конкретной страницы — также ссылку на нее. Ссылка на коммит может дополнять ссылку для просмотра.
- Если отправка или публикация заблокирована либо еще выполняется, сообщать фактический статус.

## UI-кит и новые страницы

- Эталон — действующая `design-test.html`. Справочник существующих элементов — `ui-kit.html`, общие цвета и типографика — `ui-kit.css`; компоненты — `design-test.css` / `design-review.css`.
- Новые дизайнерские страницы подключают общие стили и `design-scale.js` с теми же артбордами 1440/1200/640/320. Использовать существующие токены и компоненты; не задавать собственные размеры заголовков, шрифты, цвета или новые виды кнопок без прямого согласования с пользователем.
- Учитывать вложенный масштаб hero главной: 41 px в холсте 1200 соответствует 49,2 px в макете 1440. Вне внутреннего hero-холста использовать `--ui-h1-size`, внутри — `--ui-h1-canvas-size`; не применять масштаб дважды.
- Новые компоновки допустимы с существующей типографикой и элементами. Тексты брать из прототипа без новых слоганов или обещаний. Варианты двух блоков логистики показывать статично, со всеми описаниями сразу.
- Перед публикацией новых страниц сверять ключевые стили с главной на одинаковых артбордах. Саму главную не менять визуально при выделении общих стилей.
